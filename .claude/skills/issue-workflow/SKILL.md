# 이슈 분석 및 구현 워크플로우

이슈 $ARGUMENTS 에 대해 다음 2단계를 **순서대로** 실행합니다.

## 워크플로우 개요

| Phase | 에이전트 | 역할 |
|-------|---------|------|
| 1 | `github-issue-analyzer` | 이슈 분석, 브랜치 생성, 영향 코드 파악 |
| 2 | `issue-implementation-expert` | 분석 보고서 기반 코드 구현 |

---

## Phase 1: 이슈 분석

Task tool을 사용하여 `github-issue-analyzer` 에이전트를 호출합니다.

**프롬프트에 포함할 내용:**
- 이슈 정보: `$ARGUMENTS`
- 다음을 수행하도록 지시:
  1. 이슈 내용 파악
  2. 관련 브랜치 생성
  3. 영향받는 코드 분석
  4. `issue/` 디렉토리에 분석 결과 저장

**완료 후:**
- 분석 보고서 파일 경로 확인 (보통 `issue/issue-{번호}-{설명}.md`)
- Read tool로 분석 보고서 내용을 읽어 Phase 2에 전달할 준비

---

## Phase 2: 코드 구현

Task tool을 사용하여 `issue-implementation-expert` 에이전트를 호출합니다.

**프롬프트에 포함할 내용:**
- Phase 1에서 생성된 분석 보고서의 경로
- 분석 보고서의 핵심 내용 (영향 파일, 구현 권장사항 등)
- 다음을 수행하도록 지시:
  1. 분석 보고서의 권장 구현 순서 따르기
  2. DDD 패턴 준수
  3. 단위 테스트 작성
  4. 테스트 실행 및 검증

---

## 에러 처리

- Phase 1 실패 시: 전체 중단, 이슈 번호/URL 확인 요청
- Phase 2 실패 시: 에러 내용 보고, 분석 보고서는 유지되므로 재시도 가능
